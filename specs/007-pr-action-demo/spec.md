# PR mode, Action, demo and repository

Status: implemented

## Context

`pr` exports the full tree of two revisions with Git plumbing, scans both with deterministic rules only, diffs the findings as multisets and writes a compliance sentence per added or resolved finding. A composite GitHub Action wraps the CLI with `--llm none`, so it needs no secret.
`npm run demo` rebuilds a two-commit copy of the fixture, runs `pr` and `scan` with the scripted fake and prints the hero block; goldens and the README blocks are generated by `npm run regen`.
The repository process is part of the product: `AGENTS.md`, a pre-commit hook, `check:secrets`, CI with a self-action job, ADRs and diagrams validated by `npm run diagrams:check`.

## Acceptance criteria

- **PR-01** When `pr --base <ref>` runs, the system shall list changed files with `git diff -z --name-only --diff-filter=ACMR <base>...<head>`; if no changed file is a supported kind it shall skip both scans and say so; otherwise it shall export the full tree of each revision with `exportTree` into a temporary directory, scan each tree as a normal target with deterministic rules only, and remove the directory afterwards, so that a change to `schema.prisma` alone changes the findings of an unchanged TS file that uses the model.
- **PR-02** When base and head findings are diffed, the key shall be the `FindingKey` of section 4.4 (`ruleId`, `categories.join(",")`, `sinkKind`, `vendor`, relative path, hash of the normalized masked snippet) and the diff shall be computed on multisets of keys (count-based), so that moving a line without changing it is `unchanged` and removing one of two identical calls is one resolved finding.
- **PR-03** When findings are added, the comment shall contain one sentence per added finding of the form "This PR introduces a new flow of <category> to <sink description> at <file:line> (LGPD <arts>; GDPR <arts>)." for sink rules and the rule-specific template for the others, and "This PR removes …" for resolved ones, with the disclaimer footer.
- **PR-04** When the two-commit demo repository is diffed, the system shall report exactly two added findings (`PR-ANALYTICS` and `PR-TRANSFER`, both at `src/analytics.ts:9`, with `identifier.cpf` and `special.health` to Mixpanel), one resolved finding (`PR-FILE` at `src/patients.ts:24`) and 15 unchanged, and exit 1 under `--fail-on error`.
- **PR-05** If more changed files than the PR cap of section 6.1, or Git fails, then the system shall exit 2 with `PR_TOO_LARGE` or 3 with `GIT_ERROR`.
- **PR-06** If `--base` or `--head` starts with `-` or does not resolve to a commit through `git rev-parse --verify --end-of-options <ref>^{commit}`, then the system shall exit 3 with `GIT_ERROR` before any other Git call.
- **ACT-01** When the repository's CI runs the composite action with `uses: ./` on the fixture with `fail-on: none`, the action shall produce `findings.sarif` and the job shall validate it with `catalog --validate-sarif`.
- **ACT-02** The action shall run the CLI from `$GITHUB_ACTION_PATH` with `--llm none`, so that no secret is needed and Node strips types outside `node_modules`.
- **ACT-03** `docs/github-action.md` shall contain a complete user workflow with `github/codeql-action/upload-sarif@v4` and `permissions: security-events: write`.
- **ACT-04** When the CLI inside the action exits with code 1, the action shall still write the `sarif-file`, `comment-file` (PR mode) and `exit-code` outputs and append the PR comment to `$GITHUB_STEP_SUMMARY` before exiting with that code; `action.yml` shall capture the code with `|| code=$?`.
- **DEMO-01** When `npm run demo` runs with no `.env`, no key, no `PRIVACY_RADAR_CLOCK` and the network guard, it shall exit 0, write `artifacts/demo/` with the files of 5.1, and print the summary of 10.2 and the PR comment with the default clock.
- **DEMO-02** When `npm run demo` runs with `LLM_API_KEY` set in the environment and without `--live`, it shall still use the fake and print `provider: fake (scripted)`.
- **DEMO-03** The README block between `<!-- demo:start -->` and `<!-- demo:end -->` shall equal `tests/golden/demo/demo-summary.txt`, and the counts in it shall equal those in `tests/golden/demo/findings.json`.
- **REP-01** `AGENTS.md` shall have at most 100 lines.
- **REP-02** `.env.example` shall list every variable read by `envSchema`.
- **REP-03** If any test attempts a connection through `fetch`, `net`, `dns`, `http` or `https`, then the guard shall fail it with `NetworkDisabledInTests`.
- **REP-04** The dependency rules 1 to 7 of section 4.3 shall hold for every file under `src/`.
- **REP-05** The repository shall contain no `TODO`, `TBD`, placeholder text or key-shaped string in versioned files outside `tests/`, `.githooks/pre-commit` shall exist and be executable, and the disclaimer sentence shall appear in every template and in the table output module.
- **REP-06** `scripts/check-catalog-freshness.ts` shall exit 0 with a warning line when `checkedOn` is older than 180 days and exit 1 only with `--strict`.

## Non-goals

- **npm publication, Marketplace listing.** Owner rule: nothing is published before validation. The Action runs from a checkout (`uses: flaviorg/privacy-radar@<sha>` after publication).
- **Windows.** Portable by construction (`node:path`, no shell-specific scripts); CI on Ubuntu only.
- **Coverage gate.** Reports only; a gate on a code base with many fixture files would invite inflation.
- **A web UI or dashboard.** incident-copilot covers UI. The CLI, SARIF in GitHub code scanning and Markdown documents are the interfaces.

## Resolved questions

- **Docs, CI, hook and repo specs move to the last milestone (Spec delta 7).** Numbered M10 so spec M9 (optional) keeps its number.
- **Portable scripts (Spec delta 8).** `regen` is `node scripts/regen.ts`; `eval:live` passes `--write auto`.
- **Git helpers for scripts (Spec delta 9).** `src/infra/git.ts` has `initRepo` and `commitAll` (hermetic identity and config), used by `scripts/demo.ts` and `tests/helpers/git-repo.ts`.
- **PR verdict (Spec delta 11).** The `pr` exit code counts added non-suppressed deterministic findings at or above `--fail-on`; both revisions are scanned with the base revision's `privacy-radar.config.json` when present (changed in the final review: scanning each revision with its own config let a pull request suppress its own findings); a PR that changes the config says so in the comment.
- **Review focus 4.** Refs such as `origin/main`, `feature/x` and a 40-character SHA are accepted; only a leading `-` or a non-commit is rejected, before any other Git call.
- **Step 0 Git results.** `git diff -z --name-only` prints non-ASCII paths unquoted; `GIT_INDEX_FILE=<tmp>/index git read-tree` plus `git checkout-index -a --prefix=` writes a tree without touching the repository index; two hermetic commit runs give the same SHA. See `docs/api-notes.md`.
- **CI (ACT-01).** The `self-action` job runs only on GitHub after publication; its local proof is `tests/e2e/action.e2e.test.ts`, and the static test in `conventions.unit` checks the workflow file.
